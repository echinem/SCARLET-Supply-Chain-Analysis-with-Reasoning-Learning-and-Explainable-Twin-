# Causally-Aware Supply Chain Digital Twin - Comprehensive Project Analysis

## Overview
This platform models complex supply chains as dynamic, interactive graphs, running on a highly responsive Next.js/ReactFlow frontend and a FastAPI/Celery/Neo4j/Redis backend. It supports simulating structural disruptions, probabilistic cascading failures, and uses AI optimization logic for inventory rebalancing and route easing.

## Architecture Properties
### Backend (Python 3.11+, FastAPI)
- **Neo4j**: Graph database prioritizing structural topology (nodes, edges).
- **Redis**: High-speed caching for active simulation state, Celery message broker.
- **NetworkX**: In-memory graph math for incredibly fast discrete-event simulation ticks, avoiding DB I/O bottleneck.
- **Celery**: Distributed task queue for non-blocking simulation execution.

### Frontend (Next.js 14, React, Zustand, ReactFlow)
- **ReactFlow**: Used for the macro/micro canvas, coupled with a `dagre` auto-layout to neatly arrange Supply Chain echelons (Suppliers $\to$ Factories $\to$ Warehouses $\to$ Hubs $\to$ Customers).
- **Zustand**: Fast client-side state management, pushing real-time UI updates by polling Redis metrics every 500ms during active simulation batches.
- **Framer Motion**: Smooth DOM micro-interactions, transitions, and pulsing risk indicators.

## Detailed File-by-File Analysis

### Backend Structure (`backend/app/`)

**1. Root & Core Setup**
- `main.py`: The FastAPI application entry point. Handles `lifespan` startup logic with exponential backoff retries for Neo4j and Redis connectivity. Adds CORS middleware for local frontend connections and registers all API routers.
- `celery_app.py`: Configures the Celery worker (`digital_twin_worker`), mapping both the message broker and backend result store to Redis.
- `core/config.py`: Pydantic `BaseSettings` component that loads and types environment variables (`DB_URI`, `REDIS_URI`, etc.).
- `core/logging.py`: Standard Python logging configuration for structured `sys.stdout` streaming.

**2. Database Connectors (`db/`)**
- `init_neo4j.py`: An idempotent script triggered on startup. It ensures unique property constraints on Node IDs and Relationship IDs, and establishes indexed lookups for `risk_score` for high-performance traversals.
- `neo4j.py`: Manages the async Neo4j driver connection pool and provides a session generator dependency for FastAPI routes.
- `redis.py`: Async Redis client manager for FastAPI routes to fetch realtime simulation state.
- `postgres.py`: SQLAlchemy async engine setup. (Presently scaffolded, but Neo4j/Redis are the main drivers).

**3. API Routes (`api/`)**
- `dev.py`: Development endpoints (`/seed`, `/clear`). The `/seed` endpoint rapidly synthesizes a connected 15-node, multi-echelon supply chain.
- `graph.py`: RESTful endpoints for granular Node/Edge CRUD operations, alongside a bulk `/import` endpoint.
- `health.py`: Diagnostics endpoint verifying parallel connectivity to Postgres, Neo4j, and Redis.
- `simulation.py`: Simulation entry points. `/simulate` triggers a Celery task and initializes Redis state tracking. `/status` and `/metrics` are high-frequency endpoints dedicated to answering UI polls.

**4. Business Logic Services (`services/`)**
- `dev_service.py`: Contains the hardcoded schema for the seed network payload (Nodes: `Port`, `Supplier`, `Factory`, `Warehouse`, `Customer` and Edges).
- `graph_service.py`: Executes data layer Cypher queries. The `import_subgraph` function leverages highly optimized Neo4j `UNWIND` logic to batch create nodes/edges cleanly in a single ACID transaction.
- `snapshot_service.py`: Connects synchronously to Neo4j to pull the entire topological graph footprint into a Python `NetworkX.DiGraph` representing a zero-latency memory clone.
- `simulation_service.py`: The absolute core engine. It loads the `NetworkX` snapshot, applies structured disruptions against it (node failures, edge congestion spikes, demand shocks), and cycles a discrete time-step loop. For each tick, inventory is probabilistically consumed. If `decision_mode == 'ai'`, the logic dynamically reroutes edge congestion variables and parachutes surplus warehouse inventory to failing downstream nodes. The active state is dumped into a JSON serialized Redis key each tick.

**5. Workers (`workers/`)**
- `simulation_worker.py`: Binds `run_simulation()` into a Celery task (`run_simulation_task`). Encases the execution in error boundaries to push failure states back to Redis if the active engine crashes.

**6. Data Models & Schemas (`schemas/`, `models/`)**
- `schemas/graph.py`: Pydantic models for graph validation, strictly enforcing `NodeLabel` & `RelationshipType` permutations.
- `schemas/simulation.py`: Highly detailed configuration models orchestrating disruptions (`NodeFailure`, `EdgeDisruption`, `DemandSpike`, `CapacityReduction`), and formatting expected API responses.

### Frontend Structure (`frontend/src/`)

**1. Global App Setup (`app/`)**
- `layout.tsx` & `globals.css`: The Next.js Root Layout wrapper, seamlessly injecting `Geist` variable fonts. CSS contains global aesthetic defaults, removing archaic browser borders and integrating subtle global animation frames.
- `page.tsx`: The primary dashboard orchestration. Establishes the WebGL-esque grid background layout, the top HUD, status indicators (verifying API sync loops), and handles dynamic module hydration of `GraphCanvas`, `MetricsPanel`, and `SimulationPanel`.

**2. State Management (`store/`)**
- `graphStore.ts`: An incredibly dense Zustand state machine anchoring the entire client.
  - Controls global `nodes` and `edges` arrays mapped to the ReactFlow components.
  - Coordinates API syncing (`fetchGraph`, `seedGraph`, `importSubgraph`). It runs a pre-processing loop categorizing incoming backend nodes by "Supply Layer" so that `dagre` maps them effectively left-to-right.
  - Active Simulation Poller: Initiates a `setInterval` clock ticking every 500ms against the FastAPI backend, dynamically mutating the values of `inventory` and `risk_score` across nodes without unmounting them.

**3. Graph Algorithms (`lib/`)**
- `graphReasoning.ts`: A purely algorithmic, lightning-fast helper. Builds dynamic adjacency list Maps (O(1) lookups), executing localized Breadth-First-Search (BFS) queues for `getUpstreamNodes`, `getDownstreamNodes`, and highlighting `getRiskContributors` spanning the DAG. Highly critical for the AI explainability UX.
- `utils.ts`: Tailwind CSS class merging utilities (`clsx`, `twMerge`).

**4. UI Components (`components/`)**
- `graph/GraphCanvas.tsx`: The topological masterpiece. Wraps ReactFlow nodes and bezier edges in highly customized, hardware-accelerated Framer Motion components. Modifies edge geometry strokes (Amber/Cyan/Red) dynamically based on risk parameters or upstream/downstream BFS path tracing. Uses `dagre` for directed acyclic graph layout math dynamically executed.
- `dashboard/SimulationPanel.tsx`: The centralized command module floating top-left. Three interactive tabs:
  - **Engine**: Timestep ranges and tick latency sliders.
  - **Shocks**: The payload interface to queue multi-variable network bottlenecks (NodeFailures, EdgeCongestion) before unleashing the simulation.
  - **Network**: Integrated network topology CRUD layer. Forms allowing the user to seamlessly inject new nodes on the fly with targeted relationship bindings, or disintegrate edges, coupled with Admin DB sweep/seed buttons.
- `dashboard/MetricsPanel.tsx`: Glassmorphic panel locked bottom-right. Displays high-tier telemetry (Global System Inventory, Active Impact Disruptions, Master Risk Score). Distinctly visualizes a badge showcasing whether 'Human' or 'AI Optimization' strategies are actively steering the simulation.
- `dashboard/ExplainabilityPanel.tsx`: The dynamic AI context drawer. Animates into frame upon clicking any specific Node on the Canvas. Demonstrates localized Inventory vs Risk math. Computes the specific upstream supplier paths mathematically bottlenecking the subject node using BFS mappings, and produces algorithmic string syntax diagnosing the categorical failure.
